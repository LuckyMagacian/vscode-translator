# SiliconFlow 翻译方向问题分析报告

## 问题现象

从日志观察到：

1. **中文输入 → 英文输出**（错误方向）
   - 输入："输出API响应"
   - 输出："Output API response"

2. **英文输入 → 英文输出**（未翻译）
   - 输入："SiliconFlow Translation API Response"
   - 输出："SiliconFlow Translation API Response"

**期望行为**：
- 中文 → 英文 ❌
- 英文 → 中文 ✅

## 根因分析

### 实际使用的 System Prompt

```
你是一个翻译专家,擅长完成外语与中文之间的相互翻译,若当前输入中文,则翻译为英语,若是非中文,则翻译为中文.
```

### 问题点

1. **用户自定义 prompt 覆盖了默认值**
   - 用户在 VSCode 设置中配置了自定义 `translator.siliconflow.systemPrompt`
   - 该配置覆盖了代码中的默认 prompt

2. **自定义 prompt 存在逻辑问题**
   - ❌ "若当前输入中文,则翻译为英语" - 导致中文总是翻译成英语（符合问题现象）
   - ❌ "若是非中文,则翻译为中文" - 应该将英文翻译成中文，但实际未生效

3. **AI 模型理解偏差**
   - Hunyuan-MT-7B 模型可能对 "非中文" 的理解有偏差
   - 英文输入时，模型可能认为"保持原样"也符合要求

## 解决方案

### 方案 1：优化默认 System Prompt（推荐）

修改默认 prompt，使其更明确、更强制：

```typescript
你是一个专业的翻译助手。请严格按照以下规则进行翻译：

1. 如果输入文本包含中文字符，必须翻译成英文
2. 如果输入文本完全是英文或其他非中文语言，必须翻译成中文
3. 只返回翻译结果，不要添加任何解释、说明或额外的文本
4. 保持原文的格式和标点符号风格
5. 确保翻译准确、自然、符合目标语言的表达习惯

请立即开始翻译，不要回复任何其他内容。
```

**优点**：
- 更明确的规则（"必须"、"严格按照"）
- 增加"立即开始翻译"的指令
- 添加更多约束条件

### 方案 2：在代码中强制检测语言方向

在发送给 AI 之前，先检测源文本语言，然后明确指定目标语言：

```typescript
const isChinese = /[一-龥]/.test(source);
const targetLanguage = isChinese ? '英文' : '中文';

const prompt = `${this.systemPrompt}

当前输入文本语言：${isChinese ? '中文' : '英文'}
目标翻译语言：${targetLanguage}
请将以下文本翻译成${targetLanguage}：

${source}`;
```

**优点**：
- 代码层面强制指定方向
- 避免依赖 AI 的理解能力
- 更可控

### 方案 3：提示用户检查配置

在 UI 中提示用户当前的 systemPrompt 配置可能有问题。

## 推荐实施方案

**优先级：方案 2（代码强制检测）**

**理由**：
- 最可靠，不依赖 AI 模型的理解
- 即使用户配置了错误的 prompt，也能正确翻译
- 符合"翻译助手"的核心功能定位

## 实施步骤

1. 在 `SiliconFlowTranslator.translate()` 方法中：
   - 检测源文本是否包含中文字符
   - 在 prompt 中明确指定目标语言
   - 将语言检测结果添加到 user message

2. 测试验证：
   - 中文文本 → 应翻译成英文
   - 英文文本 → 应翻译成中文
   - 混合文本 → 根据主要语言判断

## 验证方法

1. 选中中文文本执行翻译，检查输出是否为英文
2. 选中英文文本执行翻译，检查输出是否为中文
3. 检查日志中的 messages 内容，确认语言检测逻辑正确
