# 翻译结果显示问题修复计划

## 问题现象

用户选中文字执行翻译后，翻译结果只在 OutputChannel（日志）中显示，没有在编辑器上方悬浮显示。

**期望行为**：翻译结果应该在编辑器上方（悬浮提示框）显示。

## 根因分析

### 当前逻辑

1. **手动翻译**（[translator.ts:54-65](src/translator.ts#L54-L65)）
   ```typescript
   const target = await this.translateText(text);
   Translator.outputChannel.show();
   Translator.outputChannel.appendLine(target);
   ```
   - 只输出到日志，不显示悬浮提示

2. **HoverProvider**（[translatorHoverProvider.ts](src/translatorHoverProvider.ts)）
   - 只显示缓存的结果
   - 需要先手动翻译过才能看到

### 问题点

- 翻译结果没有立即在编辑器中可视化显示
- 用户需要去查看日志才能看到翻译结果
- 体验不直观

## 解决方案

### 方案 1：使用 InformationMessage 显示（简单）

在翻译完成后，使用 `vscode.window.showInformationMessage()` 显示结果。

**优点**：
- 实现简单
- 结果立即显示

**缺点**：
- 不是悬浮在文字上方
- 需要点击才能关闭
- 占用屏幕空间

### 方案 2：使用 Inline Hint 显示（推荐）

在翻译完成后，使用 VSCode 的 Inline Value Hints 功能，在文字旁边显示翻译结果。

**优点**：
- 显示在文字旁边，符合预期
- 不占用额外空间
- 视觉效果好

**缺点**：
- 需要使用 InlineValuesProvider API
- 实现较复杂

### 方案 3：立即触发 Hover 显示

在翻译完成后，模拟鼠标悬停事件，触发 HoverProvider 显示。

**优点**：
- 利用现有 HoverProvider
- 显示位置正确

**缺点**：
- VSCode 没有直接 API 触发 Hover
- 需要使用 workaround

### 方案 4：使用 Decoration 显示

在翻译完成后，使用 TextEditorDecorationType 在选中文字上方添加装饰。

**优点**：
- 完全控制显示位置和样式
- 可以自定义外观

**缺点**：
- 需要管理装饰的生命周期
- 实现较复杂

## 推荐方案

**方案 1（InformationMessage）** - 快速实现，立即改善用户体验

**后续优化** - 方案 4（Decoration）提供更好的视觉效果

## 实施步骤（方案 1）

1. 修改 `translator.ts` 的 `translate()` 方法
2. 在翻译完成后，使用 `showInformationMessage` 显示结果
3. 测试验证

## 验证方法

1. 选中文字执行翻译
2. 应在编辑器上方看到翻译结果提示
3. 同时日志中也有输出
