# 翻译缓存配置优化计划

## 变更目标

优化翻译缓存机制，使其可配置、使用MD5作为缓存键、调整默认缓存大小。

## 变更内容

### 1. 缓存配置项

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `translator.cacheEnabled` | 是否启用缓存 | `true` |
| `translator.cacheMaxSize` | 最大缓存条数 | `200` |
| `translator.cacheTTL` | 缓存过期时间（分钟） | `30` |

### 2. 缓存键策略

**原策略**：`provider:text`
- 问题：长文本占用大量内存

**新策略**：`provider:md5(text)`
- 使用MD5哈希生成固定长度键
- 减少内存占用
- 相同内容（即使不同provider配置）共享缓存基础

### 3. 代码改动清单

| 文件 | 改动类型 | 改动内容 |
|------|----------|----------|
| `package.json` | 新增配置 | 添加缓存相关配置项 |
| `src/constants.ts` | 新增常量 | 添加CacheEnabledKey、CacheMaxSizeKey、CacheTTLKey |
| `src/translator.ts` | 修改逻辑 | 使用MD5生成缓存键、读取配置、优化缓存管理 |
| `src/utility.ts` | 新增方法 | 添加MD5哈希函数（如果不存在） |

## 实施步骤

1. 在 `package.json` 添加配置项声明
2. 在 `constants.ts` 添加配置键常量
3. 在 `utility.ts` 添加MD5函数
4. 在 `translator.ts` 修改缓存逻辑：
   - 使用配置项替代硬编码值
   - 使用MD5生成缓存键
   - 检查缓存启用状态

## MD5实现方案

VSCode扩展环境无法使用Node.js内置crypto模块，需使用纯JS实现：

```typescript
// 使用简单的MD5实现（SparkMD5或自定义）
private static md5(text: string): string {
    // 使用Web Crypto API或纯JS实现
}
```

**备选方案**：
- 使用 `crypto-js` npm包（需安装依赖）
- 使用简化哈希函数（非标准MD5，但足够用于缓存键）

## 验证方案

1. 测试配置生效：修改配置项，验证缓存行为变化
2. 测试MD5缓存键：相同文本在不同位置应命中缓存
3. 测试缓存禁用：设置 `cacheEnabled=false`，验证每次都调用API

## 回退策略

保留原缓存逻辑作为fallback，如果MD5计算失败，使用原文本作为键。
