# 需求说明书

## 1. 需求背景

当前翻译插件会在每次翻译时输出详细的调试日志(API请求、响应、结果等),这些日志对于调试很有帮助,但在正常使用时可能造成干扰。用户希望:
- 能够控制是否输出翻译日志
- 开发调试时开启日志,正常使用时关闭日志
- 默认开启日志(保持当前行为)

## 2. 需求描述

### 2.1 新增配置项

在 `package.json` 的 `contributes.configuration.properties` 中新增:

1. **translator.enableLog**
   - 类型: `boolean`
   - 默认值: `true`
   - 描述: "是否启用翻译日志输出,开启后会在输出通道显示API请求和响应详情"

### 2.2 日志输出逻辑

修改 `SiliconFlowTranslator.ts` 中的日志输出逻辑:

- **原逻辑**: 无条件输出所有日志到 `outputChannel`
- **新逻辑**: 
  - 检查 `enableLog` 配置
  - 如果 `enableLog === true`,输出日志到 `outputChannel`
  - 如果 `enableLog === false`,跳过所有日志输出

### 2.3 影响范围

- `package.json`: 新增配置项
- `src/constants.ts`: 新增配置键常量
- `src/translators/BaseTranslator.ts`: 在基类中添加日志开关检查
- `src/translators/SiliconFlowTranslator.ts`: 使用基类的日志开关
- `src/translators/TranslatorFactory.ts`: 传递日志配置

## 3. 用户场景

### 场景 1: 开发调试时开启日志
- 配置: `enableLog = true`
- 行为:
  - 每次翻译时,输出通道显示:
    - API请求详情(URL、Headers、Body)
    - API响应详情(Model、Choices、Usage)
    - 翻译结果(Source → Translation)
  - 方便调试和问题排查

### 场景 2: 正常使用时关闭日志
- 配置: `enableLog = false`
- 行为:
  - 翻译正常工作,但输出通道不显示任何日志
  - 提升性能,减少日志记录开销

### 场景 3: 默认配置
- 配置: 未配置(使用默认值 `true`)
- 行为:
  - 保持当前行为,输出所有日志
  - 向后兼容,不影响现有用户

## 4. 约束条件

1. **向后兼容**: 默认开启日志(`true`),保持现有行为
2. **性能优化**: 关闭日志时,完全跳过日志构建和输出,减少开销
3. **全局生效**: 日志开关对所有翻译器生效(有道翻译、硅基流动翻译)

## 5. 验收标准

- [ ] 新增配置项在 VS Code 设置界面可见
- [ ] 配置为 `true` 时,正常输出所有日志
- [ ] 配置为 `false` 时,不输出任何日志
- [ ] 默认配置(未设置)时,行为与修改前一致
- [ ] 日志开关对所有翻译器生效
